> 配套计划：[实施计划](2026-06-14-剩余模板优化-实施计划.md)

## 1. 评审基准 rubric

| 维度 | 合格标准（来自已修模板的共性） |
|---|---|
| 章节构成 | 必含五块固定骨架：①头部元数据（`最后更新` 日期 + `状态：模板` + `类型` + `目标详细程度：L3`）；②`## 适用范围`（说明收录什么、并划清与其他模板的边界，如"材料只在丹方中提及，材料本体放材料分析模板"）；③范围约束段（物品类用 `## 前置声明`"只整理原文出现/可支撑、缺据写'原文未说明'、不为补齐梯度而虚构"；职业类可用 `## 不要写什么`）；④字段规格块（见"字段定义"维）；⑤`## 推荐结构` 含一个可直接套用的产出文档骨架。缺任意一块即不合格。 |
| 字段定义 | 必含一份逐字段规格，且对每个字段给出"写法要求/含义"而非只列字段名。两种合格形态：物品类用 `## 必须写什么` 表格（`\| 字段 \| 写法要求 \|`，逐字段说明取值口径，如"稀有度=按作品自己的描述填写"）或逐字段 bullet（功法/秘境）；职业类用 `\| 模块 \| 必写内容 \| 项目用途 \|` 三列表 + 多个 `### 子模块` 段落释义。所有"无据"字段须明确允许写 `原文未说明`。只罗列字段名、无释义/取值口径者不合格。 |
| 数据来源标注 | 推荐结构骨架的头部必须固定带 `资料来源：` 行，指向 `docs/世界观参考/作品名/作品名.txt` 与 `.storygraph/storygraph.db`；并带 `对应模板：docs/世界观参考/模板/<本模板>.md` 行做溯源；产出文档 `状态` 须给"草案 / 原文已复核 / 待复核"枚举。缺资料来源行或对应模板溯源行即不合格。 |
| 与项目对接 | 须指明本类条目落到项目的去向。最佳做法（符师/阵法师）：在字段表设 `项目用途`/`项目映射` 列，并显式点名 `items`/`abilities`/`effects`/逃生 GA/任务奖励/建筑/地图/动态事件等 `apps/game/data/` 资产类型，符师另设 `## 游戏化抽象（我的判断）` 表。多数物品类（丹药/法宝/材料/武器/功法/秘境）当前以"用途"字段隐式对接、未单列项目映射列——按本 rubric 视为"对接偏弱"，评审时应建议补一句对应 `apps/game/data/` 资产或 wiki 条目类别。 |
| 示例 | 必须给出至少 1 个填好的样例，且样例要把每个字段/模块都填满（含示范何时写 `原文未说明`）。合格形态：物品类在推荐结构里给填好的"总表"样例行（丹药 5 行、武器 5 行等）或填好的卡片（功法"基础吐纳法/御兽诀/傀儡术"、秘境"宗门试炼秘境/古修洞府"）；职业类（炼丹师/炼器师）以逐个 `###` 子模块的释义段充当填写范例。只给空表头、空卡片占位而无任何填好内容者不合格。 |

> 说明：后续每张速评卡的"主要问题"均按本 rubric 逐维对照得出。

## 2. 项目代码 ↔ 模板对照表与缺口

> 说明：左列为项目实际维度。代码侧覆盖 `apps/game/data/` 下全部 18 个子目录（abilities / actions / balance / behavior-trees / config / definitions / economy / effects / entities / goals / items / jobs / needs / quests / relationships / tags / toils / world），外加 `docs/worldbuilding/wiki/` 四类与 ADR-058「分层时间域 / 月压缩」里程碑维度。模板名取自 `docs/世界观参考/模板/`。

| 项目维度（data 目录 / wiki 类 / 里程碑） | 已对应模板 | 缺口判断 |
|---|---|---|
| abilities（GA：战斗/逃生/神通等技能定义） | 功法术法神通、战斗与保命机制 | 已覆盖（技能数值/触发由两模板的"项目用途"列对接，符合 GAS 资产分工） |

| balance（combat/cultivation/economy/emotion/memory/obsession/personality/reaction/relationship/social/risk/utility 等平衡参数） | 境界提升与功法分析、记忆情绪与执念、NPC性格与代表事件、物资产出与消耗、拍卖坊市与交易 | 部分（多数子表有对应主题模板承载数值口径；utility/reaction/risk 决策权重无叙事侧模板，但属纯调参，可不立模板） |

| 里程碑 · ADR-058 / 相遇与剧情对话 DSL（对话候选/选项/副作用命令/剧情包状态机） | 有限视角与叙事日志、NPC性格与代表事件 | 缺（叙事日志偏事后记录，无"对话 DSL / 剧情包状态机 / 相遇剧情"模板） |
| 里程碑 · ADR-058 / 保真等级与时间域分层（Hot/Warm/Cold） | 时间行动与事件耗时 | 缺（属架构机制，世界观侧无对口模板；如需玩家侧叙事感知可考虑，但本质工程层） |

**缺口小结：** 以下条目为"有系统无模板"或"覆盖不足"，作为后续新增模板清单的输入，逐条点名：

- **势力运营 / 继承 / 危机动态规则**：`wiki/rules` 下 `leader-succession`（掌门继承）、`faction-crisis-defection`（势力危机与叛逃）、`wealth-exposed`（暴富露财）已有规则落地，但「势力设定」模板偏静态结构（势力类型/资源），缺承载"势力运营、掌门更替、危机叛逃"这类**动态势力规则**的模板。建议新增「势力运营与权力更替」类模板。
- **ADR-058 · 事件因果链 / 长程因果图**：现有「冲突事件分析」「动态事件与机会点」按单个事件组织，月压缩里程碑要求的"事件因果链 / 多月因果图"组织视角无模板。建议新增「事件因果链」模板。
- **ADR-058 · 月度 episode 与地点轨迹**：远处 NPC 的月压缩产出是"压缩态经历摘要 + 地点轨迹"，与「时间行动与事件耗时」（逐日耗时）、「出门游历流程分析」（单次游历）粒度不同，无对口模板。建议新增「月度经历摘要与地点轨迹」模板。
- **ADR-058 · 相遇与剧情对话 DSL**：对话候选/选项/副作用命令/剧情包状态机为里程碑核心，现有「有限视角与叙事日志」偏事后日志，缺"对话 DSL / 剧情包状态机 / 相遇剧情"模板。建议新增「相遇剧情与对话设计」模板。
- **ADR-058 · NPC 长程离线演化聚合**：「角色修炼历程」「人物关系与事件分析」「物资产出与消耗」分别覆盖单维，缺"远处 NPC 一个月一次跨维（修为·境界·关系·背包·死亡）离线演化"的聚合视角模板（可作为前一条月度 episode 模板的子项，优先级次于上四条）。
- **覆盖不足但暂判无需新模板（仅记录，不进新增清单）**：`config`/`tags`（纯工程配置/登记表，世界观侧无需模板）；`balance` 的 utility/reaction/risk、`definitions` 的 combat-base-table（纯数值调参）；`actions`/`toils`/`jobs`/`behavior-trees`/`needs`（AI 行为/流程编排的机制结构维，已由「角色AI行为参考」「时间行动与事件耗时」从意图与耗时两侧间接覆盖，是否单立"机制编排"模板可在第 5 节讨论）。
- **对接偏弱（rubric 第 4 维已记，非缺模板）**：`relationships` 的 `wanted-chain`（通缉链）/`signal-rules`（声誉信号）与「信息传播与情报」模板的对接偏弱——后者偏新闻扩散，通缉/声誉链需要在该模板补一句对应 `apps/game/data/relationships/` 资产，或在第 3 节速评卡建议补"项目映射"列。
