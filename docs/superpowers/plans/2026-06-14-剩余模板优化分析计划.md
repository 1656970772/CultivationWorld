## 1. 目标产出

1. **评审基准 rubric** —— 从已修好的 10 个模板提炼"好模板长什么样"。
2. **逐模板速评卡** —— 剩余 ~27 个模板各一张卡，作为后续单独讨论的起点。
3. **缺口清单** —— 对照项目代码与里程碑，列出建议新增的模板。
4. **推荐讨论顺序** —— 逐个深聊的优先排序。

## 2. 执行步骤

1. **提炼基准（批准后第一步）**
   读 10 个修好模板，归纳共同结构特征：章节构成、是否给字段定义、是否标注数据来源（参考自哪部小说）、是否对接 game data / wiki、是否带示例。形成一张评审清单 rubric。

2. **建对照表**
   把 `apps/game/data` 的 18 类（abilities/actions/effects/entities/economy/goals/jobs/needs/quests/relationships/toils/world 等）+ `docs/worldbuilding/wiki` 四类（artifacts/characters/creatures/rules）+ 近期里程碑（月压缩事件因果图引擎）所需的世界观维度，逐项映射到现有模板，标出"有系统无模板"的缺口。

3. **逐模板速评**
   对剩余 ~27 个模板按 rubric 逐个读，产出速评卡。只给方向性意见和"建议涵盖方面"的初步清单，不写最终内容。

4. **汇总缺口**
   输出新增模板建议清单（含每个新模板要解决什么、对接哪类代码）。

5. **排序**
   综合"乱的程度 × 代码相关度 × 里程碑相关度"给出讨论顺序。

6. **落文档**
   分析结果写入本目录（`docs/superpowers/plans/`）。

## 3. 速评卡统一格式

| 字段 | 说明 |
|---|---|
| 模板名 | |
| 当前状态 | 一句话现状 |
| 主要问题 | "乱在哪"：结构 / 字段 / 与代码脱节 / 缺来源标注 等 |
| 对接的项目代码 | 关联的 `data/` 目录或系统 |
| 建议涵盖方面（草案） | 后续讨论的起点清单，**待逐项确认** |
| 优先级 | 高 / 中 / 低 + 理由 |

## 4. 不做什么（YAGNI）

- 不在本阶段改写、新建任何模板内容。
- 不对已修好的 10 个模板提修改意见。
- 不替用户最终敲定"每个模板涵盖哪些点"——那是后续逐个讨论的产物。
