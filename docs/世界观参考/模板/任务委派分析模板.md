# 任务悬赏委派分析模板

## 适用范围

本模板用于整理作品中由原文明确信息支撑的任务、悬赏与委派，包括中立机构或公共组织发布的任务，宗门、家族、学院、商会、国家、军队等势力发布或强制安排的任务，以及个人、师长、雇主、队伍或匿名委托方提出的委派。

整理范围包括公开招募、定向委派、强制征召、轮值值守、考核试炼、竞赛选拔、通缉悬赏、护送雇佣、生产上交、调查追捕、外交交涉、秘密潜伏和事后追认等形态。重点整理任务如何成立、谁负责执行、如何完成与验收、如何结算，以及任务对执行者和委托方造成的后续影响。

本模板不把普通剧情事件统一包装成任务。纯粹的组织结构、弟子流向、私人恩怨、临时打斗、自发探索、日常修炼或偶然立功，若未形成明确的发布、派遣、制度义务、悬赏条件或委托关系，不建立任务卡。原文没有任务面板时，也不改写成大型网游式任务面板。

## 整理原则

1. 先做准入判定
   满足以下任一情形，且目标或义务明确时，方可建立任务卡：存在明确发布或委托；存在正式派遣、征召或轮值义务；存在公开悬赏及对应条件；存在制度化考核、竞赛或试炼；行动完成后被权力主体正式追认并结算。只有事件发生、人物参与或结果有利于某方，不足以证明任务成立。

2. 统一覆盖各类任务来源
   不再把宗门任务、散修接活、公共悬赏和个人委派割裂处理。应覆盖中立机构、宗门势力、家族学院、商会国家、临时队伍和个人委托等来源，并区分公开发布、定向委派、强制执行、自由接取和秘密授意。作品中不存在的来源不强行补齐。

3. 排除非任务素材
   七玄门的堂口体系与弟子流向属于组织结构，不建立任务卡；王大胖与张长贵因私人恩怨组织的比武属于同门冲突，不建立任务卡。只有执法者、裁决者或委托方介入并形成正式调查、追责、裁决或悬赏流程时，才为新增的正式流程建卡，不把此前的私人事件整体改写成任务。

4. 按任务关系而非场景归类
   入门考试、墨大夫口诀考核、下山历练、升仙大会、内院选拔、火能猎捕赛等可归入考核、选拔或强制历练；血色禁地采药、燕翎堡护送、贝场值守、学院执法队值勤可分别归入采集试炼、护送、驻守和执法任务；功德院悬赏、持啸泽金剑请张衍出面对抗广源派等可归入公开悬赏或定向委派。上述素材仍须逐项通过准入判定，不因名称像任务就自动收录。

5. 一项任务一张卡
   同名任务的多次出现、规则补充、阶段变化、不同执行结果和后续结算应合并到同一张卡。若同一名称下的发布主体、执行规则或完成目标实质不同，则分别建卡，并在任务名称中写明区分项。不得用“补充”“后期版本”等方式重复建卡。

6. 不为完整而虚构
   只填写原文明确说明或能由明确情节直接确认的信息。发布者、接取条件、完成标准、奖励来源、失败后果、追责方式或委托方收益没有说明时，统一写“原文未说明”；不得用惯常设定补齐制度细节，也不得把人物猜测写成确定事实。

7. 区分名义归属与实际执行
   原文存在公开功劳、名义负责人、角色误认或幕后执行者时，应分别填写。例如七玄门奸细事件中，公开功劳归属与实际线索发现、转告过程不能混为一谈。若该事件未形成正式任务关系，只作为准入边界示例，不因事后授职而反推此前存在防谍任务。

8. 奖励、惩罚与回流分别判断
   奖励可以是灵石、贡献、资源、职位、资格、声望、人情或免罚，也可能没有物质奖励；失败后果可以是违约赔偿、扣罚、降级、伤亡、暴露或关系破裂。奖励来源、追责机制和委托方收益须分别有依据，不得因任务成功便自动补出“资源入库”“宗门稳定”等回流效果。

9. 兼顾阶段与变体
   整理长篇作品时，应兼顾前期、中期、后期以及不同势力、身份、地域、任务类型和成功或失败结局。七玄门早期考核与历练、黄枫谷入门及血色禁地试炼、迦南学院招生及内院机制、云岚宗执法、溟沧派法会与值守等应按各自任务关系判断，避免只整理主角早期经历或战斗任务，也不得把局部素材表述为全书完整体系。

   与任务相邻的资源或身份规则只写入相关字段，不单独冒充任务。升仙大会的筑基丹筛选、黄枫谷对升仙令入门者的筑基丹处置、血色禁地试炼所涉七派赌局，可并入对应选拔或试炼卡；迦南学院以扫塔、抄录卷轴、猎杀魔兽等方式获取火能，只有形成明确任务关系时才分别建卡；溟沧派上下院和弟子身份层级本身仍属于组织结构。

10. 输出保持简洁
    每张卡只保留能说明任务成立、执行、验收、结算和影响的信息，不长篇复述剧情，不重复同一规则，不在字段中加入写作指令或检索说明。

## 字段说明

- 任务名称：使用原文名称；没有正式名称时，以“发布主体或委托方 + 核心目标 + 任务形态”概括。
- 任务形态与类型：形态写公开任务、悬赏、定向委派、强制征召、轮值、考核、竞赛试炼、秘密授意或事后追认；类型写日常、生产、采集、战斗、护送、驻守、探索、调查、执法、外交、情报、潜伏、选拔等。
- 准入理由：简要说明任务关系如何成立，如正式发布、明确委托、制度要求、公开悬赏条件或事后正式结算；不复述无关剧情。
- 来源与发布主体：写中立机构、宗门、家族、学院、商会、国家、军队、队伍、个人或匿名委托方，并区分名义发布者与实际授意者。
- 接取者或执行者：写公开招募范围、指定对象、强制参与者、队伍成员及实际执行人。
- 接取或派遣方式：写自由领取、报名竞逐、上级点名、师长安排、轮值排班、强制征召、令牌传令、私下雇佣或秘密联络。
- 准入条件：写境界、身份、职位、贡献、声望、名额、队伍、前置任务、物品凭证、担保、押金、许可、保密要求和限定时段。
- 任务起因：写需求如何产生，如资源成熟、边境告急、职位空缺、试炼开启、目标被通缉、雇主需求、情报缺口或临时危机。
- 任务目标：写必须完成的行动、对象、数量、品质、地点、时限和禁止事项。
- 完成标准与验收：写成果凭证、交付对象、考核门槛、排名条件、现场确认、目标状态或其他结算依据。
- 行动流程：按实际顺序写接取或受命、准备、执行、异常处理、交付、验收和结算。
- 资源与限制：写令牌、地图、工具、丹药、法器、权限、经费、队友、护卫、情报、撤离条件，以及时间、地域、保密或行为限制。
- 报酬或奖励及来源：写物质报酬、贡献、资格、职位、指导、人情、声望、战利品分配或免罚，并写明由谁或何种资源承担。
- 失败或违约后果：写扣罚、赔偿、降级、追责、资源损失、伤亡、目标逃脱、身份暴露、关系变化或无明确惩罚。
- 结算与追责：写由谁验收、发放报酬、记录结果、调查异常、认定责任及执行惩处。
- 委托方收益或任务回流：写委托方实际获得的资源、情报、安全、秩序、人才筛选、目标处置或关系成果；没有明确结果时写“原文未说明”。
- 名义归属与实际执行：写公开负责人、功劳归属与实际发现者、执行者、幕后推动者之间的差异；不存在差异时写“一致”。
- 关系变化：写委托方、执行者、队友、竞争者、被保护者和目标之间因任务产生的信任、债务、冲突或从属变化。
- 结束方式与后续影响：写完成、失败、中止、延期、取消、转交、升级或追认，以及对资源、身份、声望、势力关系和后续任务的影响。
