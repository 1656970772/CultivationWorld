# 阵法分析模板

## 适用范围

本模板用于整理原文中有明确阵法身份或具备明确阵法结构的对象，包括阵法、禁制、结界、传送阵、封印阵、守护阵、困阵、杀阵、幻阵、隐匿阵、聚灵阵、隔绝阵、炼化阵以及由多个阵法组成的阵法系统。

以下内容通常不单独归入阵法，除非原文明确指出其属于阵法或给出足够的阵法结构证据：

- 普通法术、神通、符箓、法宝护罩及单纯的能量效果；
- 机关、陷阱、建筑设施、修炼场所及自然地形；
- 妖兽或多人同步施法形成的攻击、能量网和临时封锁；
- 仅凭名称、外观或功能推测出的阵法身份。

阵旗、阵盘、阵眼、阵基、灵石、钥匙等内容，只有在说明阵法结构时作为阵法组成或控制要素记录；若其本身是独立法宝、符箓或材料，应归入对应模板，不在本模板中展开。

## 整理原则

1. **先确认阵法身份**：原文明确称为阵法、禁制、结界、传送阵、封印阵等，或同时出现阵眼、阵基、阵位、阵纹、阵旗、主持者、供能关系等结构证据，才纳入整理。
2. **战斗型阵法提高准入标准**：除明确的阵法名称或阵法描述外，至少保留一项结构性证据，如阵位、阵眼、阵基、阵纹、主持者、供能关系、反噬机制或权限关系；不能把多人合击、能量交汇或单纯困敌效果直接当作阵法。
3. **同一阵法只保留一张主卡**：不同地点、使用者、节点、状态和版本若共享同一核心结构，归入同一主卡，在“位置与用途”“运行模式与状态切换”“强化、扩展与版本变体”中简要说明，不重复拆卡。
4. **区分阵体与附属物**：阵法本体、阵法组件、控制凭证、布阵者和阵法产物分别记录；不得把布阵者的身份、战斗行为或组件的独立功能混入阵法字段。
5. **每个字段只写字段相关内容**：只保留能够说明阵法身份、结构、功能、运行条件、状态变化和限制的总结，不引入人物经历、对话、战术细节或无关设定。
6. **静态结构与运行过程分开**：外观、阵基、阵眼、覆盖范围等写静态结构；启动、供能、判定、维持、受扰和关闭写稳定机制，不写某次使用的逐步过程。
7. **运行过程只写机制链**：可按“阵理与输入→构成与供能→启动与识别→作用与维持→受扰、降级或关闭”概括，不按时间顺序复述具体情节。
8. **效果、状态和限制分开**：效果写阵法能做什么，状态写阵法在不同运行阶段的变化，限制写无法覆盖的对象、承载上限、代价和风险，不相互堆叠。
9. **以原文为准**：事实、稳定归纳、上下文推断和未知信息分开表达；不根据阵法名称、常识或类型擅自补足属性、品阶、范围和破解方式。
10. **字段完整但内容简洁**：固定字段全部保留。原文没有信息时填写“原文未说明”“不适用”或“本次未覆盖到明确内容”，不要用大段原文填充空白。

## 信息与输出规则

- 输出结果是阵法知识卡片，不是战斗记录、布阵教程、剧情复述或证据汇编。
- 所有内容使用总结式短句，优先概括稳定事实、结构关系和运行规律；同一结论不要在多个字段重复展开。
- `布置流程`只写稳定前提和必要环节，如选址、定位、布置组件、建立连接和校验，不写某次布阵的动作顺序。
- `运行机制`写阵法的输入、识别、作用、维持和结束逻辑，不写具体人物如何应对、攻击或破阵。
- `运行模式与状态切换`、`不同状态下的表现`可统一使用“未启动/潜伏→启动/触发→稳定运行→受扰/降级→过载/失控→关闭/崩解”的状态链；只填写原文明确或能够稳定归纳的状态。
- `破解/失效/修复`只记录失效条件、薄弱环节、修复前提和可确认的恢复方式，不写具体事件过程。
- `状态沿革与后续影响`只保留会改变阵法结构、用途、版本或现存状态的关键变化，不写逐次时间线。
- 禁止写章节号、段落号、页码、场景位置、原文位置、括号出处、引用式证据和其他证据标注。不得以任何形式在字段后附加来源定位。
- 不设置“使用记录”“事件记录”或其他按事件罗列的字段；具体事件只在确实改变阵法结构或状态时，转写为对应字段中的简短结论。
