# 阵法师模板

## 适用范围

本模板用于整理作品中的阵法师职业，以及与阵法职业流程高度相关的禁制师、结界师、传送阵师、护山大阵维护者、洞府禁制布置者、阵旗阵盘制造者、阵眼阵基维护者、破阵者、解禁者和封印阵主持者。

本模板重点分析阵法职业如何运转，包括身份与稀缺性、传承与知识、阵图和布阵法器、材料与环境、选址布阵、启动维护、修复破阵、成本风险、委托收益和职业成长。单独出现的阵法名称，可以作为阵法流程案例收录，但不能替代阵法师职业闭环。

本模板侧重固定或半固定空间结构，以及由阵旗、阵盘等工具展开形成的阵法、禁制、结界、传送、封印和护山防御。独立符箓、符宝和符纸体系放入 `符师模板.md`；灵兽、一般法宝、普通术法、纯机关建筑等内容，除非明确参与阵法结构或职业流程，否则不在本模板展开。

## 整理原则

1. 先做准入判定

   可收录明确称为阵法、禁制或结界的固定或半固定空间结构，也可收录通过阵旗、阵盘、阵眼、阵基、阵纹、灵石、地脉等要素完成的布置、启动、维护、修复和破解流程。墨大夫在石室以野兽骨粉画出的奇怪阵法，可以作为用途未明的阵法事件候选；百药园禁制与禁制令牌、岳麓殿传送阵、迷踪旗与小型迷踪阵、颠倒五行阵和古传送阵修复，都符合阵法流程边界。

   云翅鸟监视韩立属于灵兽追踪，不是监视阵法或辅助禁制，应排除或移入灵兽、侦察类模板。普通侦察、一般护罩法宝、单次术法控制、独立符箓效果和纯机关陷阱也不得因功能相似而误收，除非它们明确构成阵法空间结构或参与阵法职业流程。

2. 区分阵法师职业案例与阵法事件

   阵法师职业案例必须出现职业身份，或命中传承、阵图、工具制造、材料准备、选址布阵、启动维护、修复破阵、委托收益、失败风险等职业环节。只出现阵法效果而没有职业信息时，可以记录为阵法事件，但不得据此推断操作者是阵法师。

   战斗中的多人站位或合击要二次判定。九天雷狱阵由多人结阵、多人充当阵眼，阵眼被破坏会引发重伤或反噬，可作为阵法事件；若没有布阵者、阵图、阵旗阵盘、维护流程或职业身份，则不能升级为阵法师职业案例。

3. 区分明确内容与推断

   阵法存在、使用者、工具、流程、效果和代价分别判断明确程度。墨大夫确实画出奇怪阵法，但阵法名、启动方式和具体效果均未说明；标题应写“墨大夫石室奇怪阵法”或“用途未明的仪式阵法”，不得直接定名为“夺舍阵法”。与夺舍或续命有关只能写入“不确定/推断”。

4. 同一阵法归并整理

   同名阵法在后续出现新的工具、材料、布置方法、用途、限制、修复方式、破解方法或成本时，补入同一张主卡；不同地点或不同操作者的独立实施过程，可在同卡中分项记录。阵法师人物的身份、传承、作品、委托、收益和职业风险归入人物职业卡，不为每次提及重复建卡。

5. 强制体现职业闭环

   每张卡都要填写“职业闭环命中项”。职业人物卡至少写明身份，以及传承、工具、流程、收益或风险中的一项；阵法流程卡至少写明阵法对象，以及工具材料、空间环境、操作流程、运行效果或失败风险中的一项。没有命中任何职业或阵法结构环节的内容不建卡。

   辛如音的阵法师身份、布阵法器制作、古传送阵修复、修复方法、阵法心得和阵法道书，可以形成职业闭环。天星宗以阵法扬名，并通过阵旗阵盘等禁法类法器换取灵石和材料，则体现阵法产业、职业收益和势力分工。

6. 写清工具、材料和空间流程

   布阵过程按实际出现的信息填写选址、勘察、阵旗位置、阵盘埋设、阵眼阵基、阵纹符纹、灵石供能、地脉连接、启动、维护、修复和收阵。颠倒五行阵的十八块阵盘、三十六根阵旗、玉简布置方法、按位置插旗埋盘和阵眼嵌入灵石，应归入对应字段；古传送阵的破损、复制样式、寻找阵法师、采购材料、按图修复和确认另一端是否存在，应整理为修复流程和风险条件。

7. 同时记录成本、收益和职业约束

   阵法不得写成无成本能力。灵石消耗、材料损毁、符纹偏差、阵眼暴露、误传送、封印破裂、主持者反噬、地脉受损、维护时间和多人协作都属于成本或风险。传送阵收费、守阵职位、洞府委托、护山维护、阵旗阵盘售卖、破阵报酬和势力资源交换属于收益或职业生态。

   阵法师数量稀少、钻研阵法会占用修炼精力，以及齐云霄背后的阵法师朋友、辛如音和天星宗阵法产业等内容，可以用于说明职业门槛、稀缺性和被觊觎风险，但不能脱离具体职业环节写成泛泛人物介绍。

8. 保持跨阶段和跨类型覆盖

   整理时应兼顾职业身份、阵法物、布阵事件、禁制结界、传送阵、破阵解禁、成本风险和收益委托，并覆盖不同人物、势力、地域和作品阶段。不能只收录早期显眼片段；《凡人修仙传》中还应检查百药园禁制、岳麓殿传送阵、迷踪旗、颠倒五行阵、辛如音、天星宗阵法产业和古传送阵修复等完整链条。

   飞行禁制、合击阵法、阵眼、护阁大阵、阵法封印、化龙魔阵、噬灵绝生阵，以及洞府禁制牌符、阵法闭合后内外隔绝、杀阵防御、破禁和阵法深研等内容，应逐项判断纳入或排除，不能因已有报告缺失而视为作品中没有阵法内容。

9. 对检索结果做语义消歧

   阵法师、禁制、结界、传送阵、阵盘、阵旗、布阵、破阵、阵眼、阵基、阵图、护山大阵、令牌和阵法道书等词可用于发现候选，但不能只凭词语出现建立卡片。例如“一阵眼花缭乱”中的“阵眼”不是阵法结构，应排除；功能近似的灵兽监视也不能替代阵法边界判断。

10. 缺失处理与输出自检

    输入材料缺失时写“数据缺失，不补写”；已经检查但没有相关内容时写“未检出”；尚未检查时写“未覆盖”。完成后检查：是否误收灵兽、普通法宝、一般术法或纯机关，是否把推断写进标题，是否遗漏阵法师身份和职业闭环，是否只写效果而没有工具材料与操作流程，是否遗漏成本、收益、限制和失败风险，以及同一阵法是否被拆成重复卡片。

## 字段说明

- 案例类型：填写阵法师职业、阵法物、布阵、启动、维护、修复、破阵、解禁、传送、封印、阵法产业或战斗阵法等。
- 边界判定：说明该对象为何属于阵法师职业或阵法流程；若只是灵兽、普通法宝、一般术法、符箓或机关，应排除，不建卡。
- 明确程度：填写“原文明确”“上下文推断”或“原文未说明”。同一卡不同信息的明确程度不一致时，在对应字段中分别注明。
- 使用者/职业身份：写阵法师、布阵者、主持者、维护者、修复者、破阵者、守阵人员和所属势力；身份未说明时不得自行补充。
- 职业闭环命中项：从身份、传承、阵图、工具、材料、选址、布阵、启动、维护、修复、破阵、收益和风险中填写实际出现的项目。
- 阵法对象：写护山大阵、洞府禁制、传送阵、封印阵、杀阵、困阵、幻阵、聚灵阵、阵中阵或无名阵法等。
- 场景与用途：写宗门防御、洞府保护、远程传送、秘境进入、战场困杀、隐匿、聚灵、镇压、隔绝或仪式等。
- 传承与知识：写阵图、玉简、阵法道书、师承、势力秘传、个人心得、修复图纸和布阵要诀；没有说明时写“原文未说明”。
- 工具/材料/环境：写阵旗、阵盘、阵眼、阵基、灵石、地脉、灵脉、空间材料、阵纹符纹、主持者、护法、地形和时间等。
- 操作流程：按实际情况写选址、勘察、插旗、埋盘、立阵眼、刻纹、供能、启动、维持、改阵、修复、破阵和收阵，不补写作品没有呈现的标准流程。
- 产出或效果：写防御、困敌、杀伐、幻术、传送、封印、聚灵、侦测、隐匿、镇压、隔绝、反击或改变战场等结果。
- 成本与风险：写灵石和材料消耗、阵眼暴露、误传送、符纹偏差、阵法反噬、主持者受伤、地脉受损、被敌人破解或反控等。
- 限制：写境界、神识、权限、地形、坐标、材料品质、布置时间、阵图完整度、多人协作和目的地状态等限制。
- 收益与职业影响：写委托报酬、收费、职位、阵法物售卖、材料交换、职业稀缺性、修炼时间占用和被觊觎风险等。
- 未说明项：集中列出阵法名、布阵者、阵眼、阵基、启动方式、效果、代价和限制等尚未说明的信息；没有则写“无”。
- 不确定/推断：集中填写只能由上下文推测或存在矛盾的内容；没有则写“无”。
