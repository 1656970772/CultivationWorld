# 建筑设施与场所功能模板

## 适用范围

用于整理不宜归入势力内部结构、秘境遗迹、交易流程或宗门任务制度的中立场所、公共设施、特殊功能建筑与独立功能地标。

最终输出文档只按本模板中的案例格式和字段输出；不要额外添加模板未要求的章节、说明或扩展内容。

## 前置声明

- 尽量覆盖多境界、多身份、多地域、多势力、多场景和多结局样本；不要只写主角、单一境界、少数名场面或少数成功案例。
- 只写原文、资料来源或可靠依据能支撑的内容。缺失字段写“原文未说明”；信息不足但有保留价值的对象先放入 `### 待定案例`；不得为补齐结构而虚构。
- 本文不写总览、证据段、项目字段映射或游戏化抽象；只整理值得独立收录的场所功能与事件链。
- 普通宗门内部设施放入 `势力设定模板.md`；秘境、遗迹、洞府、试炼地、禁地放入 `秘境遗迹与机缘模板.md`；拍卖、坊市、黑市等交易流程放入 `拍卖坊市与交易模板.md`；任务发布、贡献兑换和晋升考核放入 `宗门任务体系模板.md`。

## 必须写什么

本部分是参考整理范围/字段提示，不是封闭清单，也不是只能写这些；原文有相关内容可继续补充。

优先收录具备“中立 / 公共 / 特殊 / 跨势力 / 事件触发”价值的场所；只写名称和外观不够，要写清它如何被使用、由谁维护、产生什么收益或风险。

| 类型 | 示例 | 重点 |
|------|------|------|
| 中立交通设施 | 传送阵、飞舟港、渡口、驿站、空间通道、界门 | 通行条件、路线记录、封锁、偏差、偷渡和埋伏风险 |
| 公共服务设施 | 客栈、医馆、寄存处、租赁洞府、避难所、临时营地 | 禁斗规则、费用、疗伤、藏身、寄存、保密和泄密风险 |
| 检测与登记设施 | 测灵台、血脉照验台、身份登记处、通缉照影壁、鉴定台 | 检测流程、公开性、复核、身份暴露和资格结果 |
| 封印与镇压设施 | 镇魔塔、镇魂碑、封印井、镇压阵台、灾害隔离阵 | 维护方式、失控条件、公共安全、破封和灾害外泄后果 |
| 独立功能地标 | 无主灵泉、雷池、地火口、寒潭、风穴、灵眼、空间裂缝观测点 | 使用条件、自然周期、修炼/采集产出、争夺和反噬 |
| 公共事件场所 | 斗法台、论道台、法会场、公开裁决场、临时征召点 | 公开规则、见证、名声传播、群体任务和冲突升级 |

每个正式案例按以下字段写：

| 字段 | 写法要求 |
|------|----------|
| 设施名称和类型 | 写具体名称，并归入上表类型；类型不清时按原文功能描述。 |
| 所属地点或控制者 | 写所在区域、城池、商路、边境或看守者；若声称中立，要写中立来源。 |
| 中立性或开放性 | 写是否多方可用、是否只看费用/令牌/规矩、是否被某势力暗中控制。 |
| 空间与布局 | 写入口、核心区域、等候/登记/守卫位置、逃生路线、危险区和与流程相关的布局。 |
| 主要功能 | 写通行、疗伤、住宿、检测、登记、镇压、避难、裁决、集结、短期修炼等。 |
| 特殊用处 | 写跨域传送、识破伪装、验证血脉、封锁灾害、镇压邪物、隔绝神识、触发公共事件等；没有则写“原文未说明”。 |
| 使用者 | 写散修、宗门弟子、商队、凡人、妖族、逃亡者、追杀者、管理者、围观者等。 |
| 进入条件 | 写费用、令牌、身份、介绍人、开放时间、境界限制、许可、血脉、紧急状态等。 |
| 使用流程 | 写抵达、登记、缴费或验令、等待、使用、记录、复核、离开或异常处置。 |
| 消耗 | 写灵石、材料、时间、名额、人情、隐私暴露、登记身份、伤势或失败代价。 |
| 产出 | 写位移、通行资格、恢复、藏身、检测结果、身份记录、材料、感悟、情报或公共消息。 |
| 限制与周期 | 写距离、次数、冷却、开放时段、自然周期、名额、身体承受上限、战时封锁等。 |
| 维护与管理 | 写阵法师、掌柜、医修、守卫、裁判、城卫、记录者、巡逻队、供能和违规惩罚。 |
| 风险 | 写身份暴露、追杀堵门、传送偏差、设施被攻破、封印松动、反噬、管理者偏袒等。 |
| 相关事件 | 写逃亡、追杀、疗伤、检测争议、封印破裂、地标争夺、公开裁决、临时征召等。 |
| 后续影响 | 写换地图、被追踪、获得资格、结识关系、名声传播、秩序变化、灾害爆发或新任务链。 |

## 案例

### 案例

#### 案例 1：场所功能卡片

设施名称和类型：写具体设施名称及类型，如传送阵、客栈、测灵台、镇魔塔、无主灵泉、斗法台等。

所属地点或控制者：写所在地点、维护者或控制势力；中立场所需说明中立依据。

中立性或开放性：写对谁开放、按什么规则开放，是否存在暗中控制、歧视、封锁或例外。

空间与布局：写与进入、等待、使用、守卫、逃离、埋伏、隔离或围观有关的空间结构。

主要功能：写原文明确呈现的普通功能。

特殊用处：写普通功能以外的关键用途；原文未说明则写“原文未说明”。

使用者：写实际使用、管理、旁观、追击、破坏或被牵连的人群。

进入条件：写费用、身份、令牌、境界、时间、许可、规则、特殊血脉或紧急状态。

使用流程：写从抵达到离开的完整过程；如果只出现片段，按原文片段写并标出缺口。

消耗：写使用过程付出的资源、时间、身份暴露、人情或失败代价。

产出：写角色、组织或公共秩序得到的结果。

限制与周期：写次数、冷却、开放周期、自然波动、距离、名额、承受上限或封锁条件。

维护与管理：写维护者、供能、巡检、记录、守卫、收费、裁决、惩罚和异常处理。

风险：写使用失败、规则失效、泄密、追杀、失控、反噬、争夺或灾害扩散。

相关事件：写该场所参与或触发的事件。

后续影响：写对角色路线、关系、消息传播、区域秩序、资源争夺或后续任务的影响。
