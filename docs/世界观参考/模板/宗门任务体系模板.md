# 宗门任务体系模板

# 规范

本模板用于整理宗门或组织如何发布任务、分配资源、考核弟子、奖励贡献、维持秩序和推动成员成长。

本文不写大型网游式任务面板，除非原文有类似制度。宗门任务不要和散修悬赏混为一类；散修悬赏、自由接活、生存任务放 `散修生存方式模板.md`。

样本应覆盖多境界、多身份、多地域、多势力、多场景和多结局；不要只写主角任务、战斗任务或成功案例。只整理原文有可靠依据的任务制度、接取条件、行动流程、奖励来源、失败后果和组织回流。

`接取条件`、`任务来源`、`任务目标`、`成功奖励`、`失败后果` 必须尽量详细；原文未说明时写“原文未说明”，不要用泛泛一句带过。同一宗门任务体系里，如果日常、战斗、探索、生产、考核、外交任务规则明显不同，应分别写成案例。

## 参考和要求

本部分是写作要求与参考整理范围。参考范围不是限定范围，仅用于提示检索方向；原文有其他相关内容也应继续补充。

- 任务类型：日常杂务、资源维护、猎妖清剿、护送驻守、秘境探索、生产上交、考核晋升、宗门大比、外交情报、卧底渗透。
- 日常任务：采药、采矿、巡逻、看守山门、打理药园、照料灵兽、跑腿送信、维护阵法、杂役、抄录文书。
- 战斗任务：猎妖、清剿邪修、追杀叛徒、护送、守矿、边境防御、宗门战争、通缉悬赏、剿灭盗匪。
- 探索任务：秘境试炼、古修洞府、遗迹发掘、地图绘制、禁地侦查、传承考核、探查异象。
- 生产任务：炼丹、炼器、制符、布阵、修复法宝、上交材料、培育灵药、饲养灵兽、炼制阵盘。
- 社交/组织任务：收徒、传功、考核、宗门大比、联姻、外交、情报收集、卧底渗透、附属势力巡查。
- 发布者：任务殿、执事、长老、堂口、药园、矿脉、灵兽园、执法堂、边境据点、掌门、情报堂、商会委托方、附属势力。
- 接取者：杂役、外门、内门、真传、执事、长老、职业堂口成员、附庸修士、客卿、强制征召人员、秘密派遣者。
- 接取条件：境界、身份、职位、贡献、声望、队伍人数、时间窗口、前置任务、物品门票、宗门许可、担保人、押金、名额、保密契约。
- 任务起因：宗门日常运转、资源成熟、边境告急、邪修作乱、秘境开启、库存不足、职位空缺、外交需求、情报缺口。
- 任务目标：采集、巡逻、守护、猎杀、活捉、护送、驻守、探索、绘图、炼制、上交、考核、谈判、潜伏、带回情报或任务凭证。
- 行动流程：接取、审核、组队、领取工具或令牌、前往地点、执行任务、处理异常、验收、交付成果、结算奖励、复盘追责。
- 所需资源：工具、令牌、地图、丹药、符箓、法器、阵盘、飞舟、传讯符、材料、工坊、队友、护卫、撤离路线。
- 奖励：灵石、贡献、丹药、功法、法宝、材料、洞府、职位、指导、人情、声望、秘境资格、免罚、晋升机会、隐藏赏赐。
- 奖励构成：宗门库存、堂口预算、矿脉收益、药园产出、商会委托、战利品、上交资源分成、长老赏赐、战争预算。
- 失败后果：罚款、扣贡献、降级、受伤、死亡、关系变差、资源损失、宗门稳定下降、被追责、目标死亡、声望受损、秘密身份暴露。
- 组织回流：资源入库、边境稳定、商路维护、弟子筛选、职业人才培养、库存补充、情报获得、盟约达成、宗门声望变化。

```md
### 药园采摘任务

- 任务名和类型：药园采摘任务；日常任务 / 生产任务。
- 发布者：任务殿、药园管事或相关执事，按作品设定填写。
- 接取者：杂役弟子、外门弟子或轮值弟子，按作品设定填写。
- 接取条件：身份层级、境界、贡献、名额、令牌、押金、担保、保密契约、队伍配置和时间窗口；没有可靠依据时写“原文未说明”。
- 任务起因：灵药成熟、药园缺人、丹房需要材料或宗门日常维护，按作品设定填写。
- 任务目标：采摘指定灵药，满足数量、品质、时限和验收要求。
- 行动流程：接取任务、领取令牌或工具、前往药园、采摘或看护、处理异常、交付成果、验收结算。
- 所需资源：采摘工具、药篓、令牌、禁制通行权限、保存容器、丹药或护身符箓，按作品设定填写。
- 成功奖励：灵石、贡献、丹药、材料分成、免罚或管事临时赏赐，按作品设定填写。
- 奖励构成：宗门库存、药园产出、丹房预算或上交资源分成，按作品设定填写。
- 失败后果：扣贡献、赔偿损失、禁接任务、受伤、灵药损毁、被管事追责；没有可靠依据时写“原文未说明”。
- 追责方式：由任务殿、药园管事、执事或执法堂登记、调查、扣罚、赔偿或重新派任务。
- 对宗门的回流：补充丹药材料、维持药园运转、筛选可靠弟子、稳定宗门库存。
- 相关人物关系：管事、同门、队友、丹房、竞争者或被保护对象之间的关系变化。
- 升级或连锁任务：引出灵药失窃、药园禁制异常、丹房需求、内门考核或派系争执。
- 结束方式与后续影响：任务完成、失败、延期、取消、升级或转交后，对角色资源、地位、仇怨、声望和后续安排的影响。
```

### 待定案例

如果原文描述符合当前模板但信息较少，先在待定案例区保留关键摘要和括号来源；后续发现新信息时，在同一条后追加摘要和括号来源；信息相对完整后，将该条移入 `### 案例`，并从待定区删除该条，括号来源不迁移到正式案例。

待定案例格式统一为：`1. 对象名称（来源），关键摘要（来源），新增摘要（来源）。`
